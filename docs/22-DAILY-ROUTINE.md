# A five-minute review routine

This is an intended routine, not a measured completion time or a promise that every request will be found.

1. **Start and reconnect.** Double-click Start ReviewRadar.command and leave that Terminal open. Open the local app. A previously loaded page can reconnect without discarding its open notes. First-time installation remains separate.
2. **Return to the right conversation.** Open Saved analyses. Search the loaded readings by account, repository, PR number or title. Load older readings if necessary. Capture date tells you when sources were read; analysis date is a separate timestamp.
3. **Recheck when you need current evidence.** Choose Check these PRs again, inspect the prefilled account/URLs, then explicitly import. Select model analysis or the non-AI chronology baseline. A new capture starts independent decisions; yesterday's notes are still in the older saved reading.
4. **Make one useful decision.** Inspect an exact reviewer passage, the full comment and any proposed later reply. Follow the GitHub link when needed. Record a concrete next inspection such as “Check whether the contour branch avoids unused min/max calculation.” Save it. Reviewed locally means you read it, not that the code is fixed or the maintainer agrees.
5. **Retain the outcome.** Reopen the saved reading or export its source-linked Markdown sheet. The original capture and model output remain separate from your note. Refreshing GitHub never silently carries the old reviewed state forward.

## When Gemma finds nothing or gets it wrong

A zero-card model result is not a clean bill. Inspect Reviewer comments without a request card and Sources. Choose Read reviewer comments without AI to create a separate source-backed reading list. It includes approvals and context; it does not classify requests or infer replies. You can save a next-inspection note and export that list without pretending the model found the ask.

For an incorrect model card, Not a request or Reply not relevant records your disagreement separately. Keep the original output available so a later reader can see what actually happened.

## What remains on GitHub

Actual fixes, tests, review replies, maintainer decisions and thread resolution remain on GitHub. ReviewRadar never performs those actions. It helps organize reading before you choose the real next step.
